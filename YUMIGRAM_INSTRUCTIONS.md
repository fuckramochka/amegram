# 🌸 Yumigram — Інструкції розробника та релізів

Цей документ є **головним стандартом розробки, версіонування та релізів** проекту **Yumigram**.
Всі правила, наведені нижче, є обов'язковими для виконання.

---

## 🚨 СТРОГЕ ПРАВИЛО: НЕ ПІДНІМАТИ ВЕРСІЮ ДЛЯ ФІКСІВ ТА МАЛИХ ЗМІН!

> [!CAUTION]
> **ПРАВИЛО №1 ДЛЯ БУДЬ-ЯКИХ ФІКСІВ, ХОТФІКСІВ ТА МАЛИХ ЗМІН:**
> **НІКОЛИ НЕ ПІДНІМАТИ `APP_VERSION_NAME` У `gradle.properties` ТА ВЕРСІЇ МОДУЛІВ У `manifest.json`!**
> 
> Підняття `APP_VERSION_NAME` (наприклад, з `12.13.7` на `12.13.8`) дозволене **ВИКЛЮЧНО** при:
> 1. Великих мажорних оновленнях функціоналу.
> 2. Оновленні базового клієнта Telegram на новіший апстрім.

## 🧩 1. Чому змінюється APK, а коли лише модуль?

| Тип компонента | Де знаходиться код | Що оновлюється | Чи потрібен новий APK? |
|---|---|---|---|
| **Ядро клієнта (Core / Activities)** | `TMessagesProj/src/main/java/org/telegram/ui/` (`MainTabsActivity`, `DialogsActivity`, `LaunchActivity`, системні стилі налаштувань) | Збирається у нативний `classes.dex` всередині APK | **ТАК, потрібен APK**, оскільки нативні класи Telegram скомпільовані в бінарник додатка |
| **Хот-модуль (Hot Module)** | `hotmodules/ui/`, `hotmodules/settings_ui/`, тощо | Окремий динамічний архів `.hmod` (маніфест + dex), що вантажиться через `DexClassLoader` | **НІ, APK не обов'язковий**, оновлюється сам файл `.hmod` |

### Приклад:
- Якщо виправляється мертва зона або блюр під папками в `DialogsActivity.java` / `MainTabsActivity.java` — це **код ядра APK**, тому збирається новий APK.
- Якщо змінюється капсула навігації, радіус карток чату чи кольори у `hotmodules/ui/` — це **код модуля**, який можна оновити як окремий `.hmod`, або посіяти разом з черговим білдом APK.

## ⚡ 2. Як оновлюються Хот-Модулі БЕЗ підняття версії

Раніше модулі вимагали нового рядка версії (`1.0.15` -> `1.0.16`), інакше система вважала їх однаковими. **Це повністю усунуто:**

1. **Порівняння за вмістом (SHA-256 та розмір)**:
   - `HotModulesManager.shouldSeedSystemModule`: якщо версія у assets та на диску збігається (наприклад, обидві `1.0.15`), менеджер звіряє SHA-256 хеш та розмір файлу.
   - Якщо вміст файлу змінився — модуль **автоматично пересіюється та замінюється**.
2. **Гаряча заміна в пам'яті (Hot-Swap)**:
   - При оновленні модуля старий `Handle` вивантажується через `dropLoaded(moduleId)`, викликається `onDetach()`.
   - Очищається кеш скомпільованого коду в `hot_dex` (`cleanDexOpt`).
   - Новий файл замінює старий (із коректним скиданням `readOnly`).
   - Створюється свіжий ізольований `DexClassLoader`, і оновлений модуль підхоплюється миттєво **без перезавантаження додатку**.
3. **Оновлення з каталогу**:
   - `HotModulesManager.checkUpdatesAsync` перевіряє SHA-256 у віддаленому каталозі навіть при однаковій версії. Якщо хеш відрізняється — показується та застосовується доступне оновлення.

## 📱 3. Як оновлюється APK БЕЗ підняття версії

Для додатка **Yumigram** більше **НЕ ПОТРІБНО** змінювати рядок версії в `gradle.properties`:

1. **Автоматичний `versionCode`**:
   - Android та оновлювачі визначають новизну білда за цілим числом `versionCode`:
     $$\text{versionCode} = 126100 + \text{runNumber}$$
   - Кожен запуск збірки в GitHub Actions автоматично має більший `runNumber` (наприклад: 171 -> 172 -> 173).
   - Відповідно `versionCode` завжди строго зростає (`126271` -> `126272` -> `126273`), навіть якщо версія залишається `12.13.7`.
2. **Робота оновлювачів (`MiogramUpdater` та `GitHubUpdater`)**:
   - Обидва внутрішні оновлювачі клієнта порівнюють `remoteVersionCode > currentVersionCode`.
   - Як тільки на GitHub публікується новий APK з більшим `versionCode`, додаток одразу бачить оновлення і пропонує користувачеві оновитися в 1 клік.
3. **Автоматичний статус Release (Latest)**:
   - За замовчуванням будь-який пуш або диспатч збирається з поміткою **Release** (`prerelease: false`, `make_latest: true`).
   - Відповідно ендпоінт GitHub API `/releases/latest` завжди віддає найсвіжішу збірку користувачам стабільного каналу.
   - Старі `.apk` з того ж релізу автоматично видаляються CI перед завантаженням свіжого білда.

## 🚀 4. Як випускати фікси (швидка шпаргалка)

### Якщо зроблено фікс:
```bash
git add .
git commit -m "fix(tabs): усунено баг інтерфейсу"
git push amegram codex/yumi-expressive-release
```
1. **Версію в `gradle.properties` чіпати НЕ ТРЕБА.**
2. CI автоматично збере APK, призначить свіжий `versionCode`, оновить реліз на GitHub та надішле APK в Telegram канал.
3. Користувачі отримають повідомлення про оновлення в додатку.

### Якщо потрібно зібрати тестову Бету (Beta):
Додайте `[beta]` у текст коміту:
```bash
git commit -m "feat: експериментальна функція [beta]"
```

### Якщо потрібно пропустити надсилання в Telegram:
Додайте `[skip publish]`:
```bash
git commit -m "chore: дрібні правки [skip publish]"
```

## 🛠️ 5. Збірка хот-модулів (`.hmod`)

Для ручної збірки модуля інтерфейсу `ui`:
```bash
./tools/yuimodules-kit/build_hmod.sh com.amegram.mods.ui.UiModule hotmodules/ui/src hotmodules/ui/manifest.json hotmodules/build
cp hotmodules/build/ui-*.hmod TMessagesProj/src/main/assets/hotmodules/
```
Після копіювання нового `.hmod` у assets під час наступного запуску або збірки клієнт автоматично виявить зміну SHA-256 та застосує новий код модуля.
